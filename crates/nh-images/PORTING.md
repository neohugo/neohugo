# nh-images — porting notes

neohugo `resources/images/**` (image config, spec parsing, processing, filters, encoders,
EXIF) on top of the Wave A crates gift, go-image, go-png (+ go-flate), libwebp-sys and
go-hashstructure. Owner and crate lead: Wave B task T10 (images).

Every processed image of a Hugo build goes through this crate: `DecodeImageConfig` names it
(`ImageConfig.key`, the imaging `SourceHash`, the filter keys), `ImageProcessor` draws it with
gift and `EncodeTo` writes the bytes. Everything is checked byte for byte against Go oracles
built for **linux/arm64** and run under `qemu-aarch64-static` (the golden build is
darwin/arm64; see "FMA sites" and "Verification").

### Stubs (explicit errors, `ErrorKind::FeatureNotAvailable`)

| feature | error text | why |
|---|---|---|
| `images.Text` | `neohugo-rs: images.Text is not supported` | needs `golang.org/x/image/font/opentype` (sfnt parser, vector rasterizer, fixed-point metrics) and the embedded Go Regular font |
| `images.Dither` | `neohugo-rs: images.Dither is not supported` | needs `makeworld-the-better-one/dither/v2` (~1,300 lines of float code with its own FMA sites) |
| smart crop (`Crop`/`Fill` with the default `smart` anchor, when the size differs from the source) | `neohugo-rs: smart cropping (anchor "smart") is not supported` | needs `muesli/smartcrop` (float image analysis with FMA sites) |
| decoding GIF, WebP, TIFF, BMP sources (`image.Decode` of `image/gif`, `x/image/{webp,tiff,bmp}`) | `neohugo-rs: decoding <gif\|webp\|tiff\|bmp> images is not supported` | not ported; the formats are registered with their magic so that they fail explicitly instead of as `image: unknown format` |
| encoding TIFF, BMP targets | `neohugo-rs: <TIFF\|BMP> encoding is not supported` | `x/image/tiff`, `x/image/bmp` not ported |

## Public API (changes to the skeleton, all unused by other crates at the time)

- `GoImage` wraps `Arc<dyn go_image::Image>` (`new`, `from_arc`, `image`, `bounds`,
  `downcast_ref`, `go_type_name`). The concrete go-image type is Go's dynamic type.
- `image::decode(r)` / `image::decode_config(r)`: Go `image.Decode`/`image.DecodeConfig` with
  neohugo's registered formats (JPEG and PNG ported, the others explicit errors).
- `image::encode_to(conf, img, w)` (Go never reads `Image.EncodeTo`'s receiver; `Image::encode_to`
  calls it).
- `ImageConfig.target_format: Option<Format>` (`None` = Go's zero `Format`),
  `ImageConfig.bg_color: Option<go_image::color::Color>` (Go `color.Color`: `color.White`/`Black`
  are `color.Gray16`, parsed colours `color.RGBA`), `ImageConfig.filter: String` (the key of
  Go's `imageFilters`, `""` = nil), `quality_set_for_image()`, `reanchor`.
- `ImagingConfigInternal.bg_color: Option<Color>`, `resample_filter: String`.
- `Image.spec: Option<Arc<dyn Spec>>` (Go's `WithImage` sets it to nil); `Image::new` takes
  `Option<Arc<dyn Spec>>`; `with_image`, `with_spec`, `init_config` (`InitConfig(r)`),
  `init_config_lazy` (`initConfig()`); the config state is shared by clones like Go's pointer,
  with Go's `sync.Once` semantics (`configLoaded` does not consume the Once).
- `Format` has Go's discriminants; `default_extension()` returns `String` (from the media type,
  like Go); `to_image_meta_image_format()`.
- `ImageProcessor::new(cfg) -> Result<Arc<_>>` builds the EXIF decoder (regexp errors);
  `decode_exif(filename, format, r)`.
- `GiftFilter` variants: `Gift(Arc<dyn gift::Filter>)`, `Overlay`, `Process`, `Mask`,
  `Padding`, `AutoOrient`.
- `to_filters(v) -> Result<Vec<FilterObject>>` (Go panics `"%T is not an image filter"`).
- `filters::Filters` has every constructor (`overlay`, `mask`, `opacity`, `padding`,
  `process`, `auto_orient`, `brightness`, … `unsharp_mask`, and the `text`/`dither` stubs), all
  returning `Result<FilterObject>` (Go panics on bad arguments; the message is the error).
- `filters::filters_key(&[FilterObject])` = Go `hashing.HashString(gfilters)` (the Filter
  key); `filters::register_hash_types()` registers `FilterObject` and `images.Color` with
  go-hashstructure (constructors call it).
- `color::Color` (an `Object`, `images.Color`), `hex_string_to_color_go` (bytes in),
  `to_color_go`, `color_go_to_color`, `add_color_to_palette`, `replace_color_in_palette`, …
- `exif::{Decoder, DecoderOption, ExifInfo, ImageFormat, ReadSeek, TagValue, Rat}`;
  `ExifInfo.date` is a `go_value::Time` (Go's zero time when absent).

## Deliberate deviations

1. **Panics become errors** (README rule 9). Where Go panics inside a gift `Draw` — the
   overlay/mask source failing to decode (`failed to decode image: …`), the padding size checks
   (`final image width will be less than 1 pixel: …`), `processFilter`/`autoOrientFilter`
   (`not supported`) — the port checks before drawing (`ImageProcessor::do_filter`) and returns
   the same message. The filter constructors return Go's panic messages as errors, and
   `to_filters` too.
2. **Sources are decoded before drawing.** Go decodes the overlay (and mask) source inside
   `Draw`, once per `doFilter`; the port decodes it once per `do_filter` just before drawing.
   Same image, same bytes (the source is always the ENCODED PNG, specs/images.md §9.10).
3. **Giphy / GIF.** GIF decoding is not ported, so no `Giphy` source exists: `resolveSrc` and
   `doFilter`'s animated-GIF branch reduce to the non-GIF path.
4. **`DecodeConfig`'s source structure.** Go's `buildConfig` merges the defaults into the input
   map itself (`maps.ToStringMapE` returns a `map[string]any`/`maps.Params` as is), so the
   namespace's `SourceStructure` is the input with the defaults merged in; the port returns
   that merged map explicitly (Go values are shared, go_value maps are not). The `SourceHash`
   is computed on the input before merging, as in Go.
5. **EXIF warnings** (`WithWarnLogger`, imagemeta's `Warnf`) are not modelled: they only reach
   the log. When Go returns a partial `ExifInfo` together with an error, the port returns only
   the error (Hugo discards the info then). Hugo's `exif failed: %v` recover replaces an
   imagemeta error, as in Go.
6. **`exif.Tags` JSON** (the `tmc` codec of `init`, `MarshalJSON`/`UnmarshalJSON`) is not
   ported: it only serves the file cache (`resources/_gen/images/*.json`), which the port never
   reads or writes (cold-cache rule, HUGO_LAYER.md §4.5).
7. **imagemeta control flow.** imagemeta uses panics (`errStop`, `ErrStopWalking`, runtime
   errors recovered by `Decode`); the port models them as a `Fail` enum and maps them to Go's
   final error exactly (`decode_result`), including the first silent EOF that leaves the stale
   read buffer in place and the doubled `invalid format: invalid format: unexpected EOF` of a
   recovered runtime error. Runtime panic messages (type assertions, slice bounds) are Go's.
8. **`ImageFormat` of `Format::Gif`/`Bmp`** is `ImageFormat::Unknown` (Go's `-1`).

## Go behaviour reproduced on purpose

- `DecodeConfig`'s error texts, including `invalid anchor value '\x00' in imaging config`
  (Go formats the zero `gift.Anchor` with `%q`) and `%!q(<nil>) is not a valid resample filter`,
  and the `failed to decode media types: ` prefix.
- The imaging `hint` config is ignored (`ImagingConfigInternal.Hint` is never set, so every spec
  without a hint gets `photo`), as in Go.
- `hexStringToColorGo`: `ffffff`/`000000` (also from `fff`/`000`) are `color.White`/`color.Black`
  (`color.Gray16`), `ffffffff` is a `color.RGBA`; rune doubling of 3/4-character codes;
  `encoding/hex` error texts.
- `uint8(opacity * 255)` converts through int32 (arm64 `FCVTZS`, saturating), e.g. opacity 1.7
  gives alpha 177 (`opacity-over` in the process fixture).
- A same-size `Resize` re-encodes; `EncodeTo` JPEG reinterprets an opaque NRGBA as RGBA.
- gowebp imports `*image.RGBA` as non-premultiplied; `ConvertToNRGBA` for other types.
- EXIF: `exifFieldsGPS` names win for ids 0x0000–0x001f; `Space separated, pick first`; time
  and GPS tags are decoded even when excluded (they feed `Date`/`Lat`/`Long`); IFD1 time tags
  pass `shouldInclude`; `ApertureValue` of a non-rational is the int `0`; zero-denominator
  rationals are `"undef"`; float/double infinities are `"undef"`; `GPSTimeStamp` of a wrong
  length is a zero `time.Time`; `GetLatLong`/`GetDateTime` type assertions panic
  (`exif failed: interface conversion: …`).

## FMA sites

Verified with `go tool objdump` of the linux/arm64 oracle binary (`-s 'resources/images\.'`):

| Go site | arm64 | Rust |
|---|---|---|
| `color.go:77` `Color.init` luminance `0.2126*r' + 0.7152*g' + 0.0722*b'` | 2 × FMADDD (the red product is rounded, then `g'*0.7152` and `b'*0.0722` are fused in order) | `color.rs:Color::init` (`mul_add` twice) |
| `resampling.go:99, 111, 124, 194, 197` | 15 (FMADDD/FMSUBD/FMADDS/FMSUBS) | in the gift crate (`gift::hugo_resampling`, `gift::bcspline`), verified there |

`toSRGB` uses `math.Pow` (`gift::gomath::pow`, the arm64 port with its own fused site), as do
imagemeta's APEX converters (`ApertureValue`, `MaxApertureValue`, `ShutterSpeedValue`); the
amd64 oracle differs from arm64 on 33 of those EXIF values and on the luminance, which is why
every fixture comes from arm64. imagemeta's other float code (`deg + min/60 + sec/3600`, rat
`Float64`) has no fusable site. gift's own sites (resize weights, `resizeLine`, the setters,
DrawAt Over, …) and go-flate's `EstimatedBits` are verified in their crates.

The process fixture has one record per operation (the processed image's Go type and bounds,
the length and SHA-256 of the encoded bytes, or the error text); `bytes.json.gz` holds the full
bytes of every 4th output under 2 KiB of the small synthetic sources. The Rust test regenerates
the synthetic sources with the same splitmix64 generator and the ported encoders and checks
their SHA-256 against the oracle's before using them. Operations Go performs but the port
reports as unsupported (TIFF/BMP targets, smart crops that reach the analyzer) are counted
and asserted to give the explicit error.

### The arm64 route

`tools/go-oracle/nh-images/regen.sh` builds each oracle for linux/arm64 with cgo (libwebp) and
zig as the C cross-compiler (`zig cc -target aarch64-linux-musl -UNDEBUG`, static
`-linkmode external`), and runs it under `qemu-aarch64-static` with `TZ=UTC`:

```sh
CC_ARM64=<zig cc wrapper> tools/go-oracle/nh-images/regen.sh            # config process exif
python3 tools/go-oracle/nh-images/exiffields.py                          # src/exif_fields.rs
```

Every fixture regenerates byte for byte (the process run takes ~20 minutes under qemu).
amd64 Go gives different results for the luminance, the EXIF APEX values and (through gift and
flate) some images, so never regenerate on amd64.

## Known gaps

- The stubs above (Text, Dither, smart crop, GIF/TIFF/BMP/WebP decoding, TIFF/BMP
  encoding).
- `resources/image.go`'s post-processing (fill with the background colour when the target has
  no alpha, Floyd–Steinberg to the source palette for paletted PNG targets) is T14's code
  (nh-resources); the process fixture covers `EncodeTo` without it. The pieces it needs are here
  (`is_opaque`, `add_color_to_palette`, `replace_color_in_palette`) and in go-image
  (`draw::FLOYD_STEINBERG`, `draw::draw`).
- The seeksnack site images themselves (private) are not in the repository; the 10 site JPEGs
  of the go-image fixtures, the 11 golden PNGs of the go-png fixtures and a synthetic
  watermark (600×480 NRGBA with alpha) stand in for them.
