# libwebp-sys — porting notes

Vendored **libwebp 1.3.2** built the way `github.com/bep/gowebp@v0.3.0`
builds it, and a port of the gowebp Go wrapper. Hugo uses it for every
`.webp` target (`resources/images/image.go` EncodeTo, WEBP case).

## Go file → Rust module map

| Go / C source (gowebp@v0.3.0) | Rust |
|---|---|
| `libwebp_src/{src,sharpyuv}/**` (libwebp 1.3.2, git subtree) | `libwebp_src/{src,sharpyuv}/**` (verbatim copy, `diff -r` identical) + `COPYING`, `PATENTS`, `AUTHORS`, `README.md`, `NEWS` |
| `internal/libwebp/*.c` stubs (`#include "../../libwebp_src/<unit>"`, generated by `gen/main.go`) | `libwebp_units.txt` (the 122 units, i.e. every `.c` under `src/` and `sharpyuv/`) compiled by `build.rs` |
| `internal/libwebp/a__cgo.go` (`-lm`), `a__cgo_src.go` (`-I../../libwebp_src`) | `build.rs` |
| `internal/libwebp/a__encoder.go` C preamble (`encodeNRGBA`, `encodeGray`) | `csrc/gowebp_encoder.c` (verbatim; `static` dropped, `gowebp_` prefix) |
| `internal/libwebp/a__encoder.go` Go part (`Encode`, `encodingOptionsToCConfig`, `boolToCInt`) | `src/encoder.rs` (`encode`, `encoding_options_to_c_config`, `bool_to_c_int`) |
| `libwebp/encode.go` (`Encode`) | `src/lib.rs` (`encode`, plus `encode_to_vec`) |
| `libwebp/webpoptions/options.go` | `src/webpoptions.rs` |
| `encode.h` (`WebPConfig`, `WebPConfigPreset` inline, ABI version) | `src/ffi.rs` |
| Go `image.RGBA` / `image.NRGBA` / `image.Gray` (Pix, Stride, Rect) | `src/image.rs` (`Image`, `PixView`, `Rectangle`, `Point`) |

## Build (byte parity of the C code)

cgo's command line (`go build -n`, go1.27.1 darwin/arm64, `CGO_CFLAGS` unset):

```
cc -I <pkgdir> -fPIC -arch arm64 -pthread -fmessage-length=0 -fno-common -I $WORK/b002/ -O2 -g -I<gowebp>/libwebp_src -c <unit>.c
```

`build.rs` uses `cc::Build::no_default_flags(true)` and passes exactly these
flags (`-fPIC -arch arm64 -pthread -fmessage-length=0 -fno-common -O2 -g`,
include `libwebp_src`), so the cargo profile (debug/release) does not change
the C code. No `-D` defines (`WEBP_USE_THREAD`, `HAVE_CONFIG_H` stay unset),
Apple clang's default `-ffp-contract=on`, NEON selected by `__ARM_NEON`.

**Verified:** every unit was compiled both ways (cgo stub in the gowebp module
dir vs. direct file with the build.rs flags) and the `objdump -d` text of all
**122/122** object files is identical
(`$S/work/libwebp-sys/objcmp/cmp.sh`).

## Public API (for `nh-images` / resources)

```rust
libwebp_sys::encode(w: &mut impl Write, src: &Image, o: EncodingOptions) -> Result<(), Error>
libwebp_sys::encode_to_vec(src: &Image, o: EncodingOptions) -> Result<Vec<u8>, Error>
Image::{Rgba, Nrgba, Gray}(PixView { pix: &[u8], stride: i64, rect: Rectangle })
EncodingOptions { quality: i64, encoding_preset: EncodingPreset(i64), use_sharp_yuv: bool }
EncodingPreset::{DEFAULT, PICTURE, PHOTO, DRAWING, ICON, TEXT}
```

Hugo's call is `EncodingOptions { quality: conf.Quality, encoding_preset:
EncodingPreset(conf.Hint), use_sharp_yuv: true }` (seeksnack: 75, PHOTO).
`pix` must start at the pixel at `rect.min` (Go's `Pix`), and gowebp encodes
`rect.max.x × rect.max.y` pixels (not `Dx × Dy`) — that quirk is preserved.
`*image.RGBA` is imported as if it were non-premultiplied (gowebp bug,
preserved). gowebp has no decoder; Hugo decodes WebP with
`golang.org/x/image/webp`.

## Deliberate deviations

1. **`ConvertToNRGBA` is not ported.** Go converts any other image kind
   with `draw.Draw(NewNRGBA(src.Bounds()), bounds, src, src.Bounds().Min,
   draw.Src)` before encoding. This crate has no Go image model; callers
   must do that conversion (with the `go-image` port) and pass
   `Image::Nrgba`. The oracle fixtures include YCbCr and Paletted sources
   whose expected bytes come from `Encode(original)` and whose input is the
   converted NRGBA, which checks this contract.
2. **Memory-safety guards.** Go indexes `&Pix[0]` (panics on an empty
   `Pix`) and hands the pointer to C without a length check. Rust returns
   `Error::EmptyPix` for the panic and `Error::PixOutOfRange` when libwebp
   would read past the buffer (Go: out-of-bounds read). Cases where libwebp
   fails before reading (non-positive dimensions, `|stride| < 4*width` for
   RGBA) still go to C and give Go's `"failed to encode"`.
3. **Gray input is copied** before the call (`encodeGray` takes a non-const
   pointer; libwebp does not write through it for this path).
4. **No leaks.** Go leaks the output when `size == 0 && output != nil`;
   Rust frees it.
5. **DSP warm-up.** libwebp is built without `WEBP_USE_THREAD`, so its lazy
   DSP initialisers are unsynchronised (Go has the same race). The first
   `encode` runs a few tiny encodes (lossy/lossless, alpha/opaque, gray,
   sharp/non-sharp) under a `std::sync::Once` so that the function-pointer
   tables are settled before parallel use. Initialisers are idempotent; no
   output change.
6. Errors: `Display` gives the Go message strings (`failed to init encoder
   config`, `failed to init lossless preset`, `failed to validate config`,
   `failed to encode`); `Error::Io` wraps writer errors (`write_all` is used
   instead of a single `Write` call).

## FMA sites

None in Rust: the only float operation on the Rust side is `quality as f32`
(Go `C.float(o.Quality)`, int→float32, round-to-nearest in both). All other
float math is in the C code, compiled with the same compiler and flags as
cgo (verified identical machine code, see above).

## Verification

* `tests/oracle.rs` — **962** fixture cases from `tools/go-oracle/libwebp-sys`
  (`-mode fixtures`), run concurrently (8 threads) and serially: 294
  synthetic images (11 sizes × NRGBA/NRGBA+alpha/RGBA/RGBA+alpha/Gray/
  YCbCr/Paletted × 4 patterns), 648 option-matrix cases (quality
  0/1/25/50/75/90/100/101/-5 × presets 0-6,-1,2^32+2 × sharp on/off, incl.
  the `failed to init encoder config` errors), 13 geometry edge cases
  (sub-images with non-zero Min, padded strides, 0×0 panic, short stride,
  16383/16384 widths) and 7 real seeksnack WebPs. All byte-identical.
* `golden_seeksnack_webps` — with `LIBWEBP_GOLDEN_PACK=$S/work/libwebp-sys/golden-pack`
  (built by `go run ./tools/go-oracle/libwebp-sys -mode golden ...`, 420 MB,
  not checked in): the exact encoder input of **every one of the 807
  `*_hu_*.webp` files in the golden site**, reproduced by the oracle's
  Hugo-chain emulation (decode → gift resize/overlay → re-encode, adapted
  from `$S/work/images/repro/full`). The Rust encoder output equals the
  golden file bytes for **807/807** (804 NRGBA, 3 RGBA inputs).
* `tests/api.rs` — `WebPConfig` layout vs. C `sizeof`/`offsetof`, encoder
  version 0x010302, the PHOTO preset config values from specs/images.md
  §6.4, buffer guards, writer errors.

Regenerate fixtures (repository root):

```
go run ./tools/go-oracle/libwebp-sys -mode fixtures -out crates/libwebp-sys/tests/fixtures/webp \
    -site $S/canon/pristine-seeksnack -golden $S/golden/canonical
```

## Known gaps

* Only darwin/arm64 with Apple clang 21 has been verified. On Linux, gcc
  defaults to `-ffp-contract=fast`, and glibc `libm` may differ from Apple's
  in the last ulp (sharp-YUV gamma tables use `pow`); a Linux build would
  need `-ffp-contract=on` (or `off`) plus re-verification against a Linux Go
  build. The x86_64 flags (`-m64` / `-arch x86_64`) are wired but unverified.
* The gowebp `dev` build tag (link a system libwebp) is not supported.
