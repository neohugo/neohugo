# go-sort — porting notes

Port of the go1.27.1 sorting algorithms, with identical element order for
comparators with ties and identical less/swap call sequences (so even
inconsistent comparators, like Hugo's template `sort` over mixed types,
produce Go's result).

## Go file → Rust module map

| Go (go1.27.1 `$GOROOT/src`) | Rust |
|---|---|
| `sort/zsortinterface.go` (pdqsort, insertionSort, heapSort, siftDown, partition, partitionEqual, partialInsertionSort, breakPatterns, choosePivot, order2, median, medianAdjacent, reverseRange, swapRange, stable, symMerge, rotate) | `src/pdqsort.rs` |
| `sort/zsortfunc.go`, `slices/zsortanyfunc.go`, `slices/zsortordered.go` | `src/pdqsort.rs` (same template, see below) |
| `sort/sort.go` (Interface, Sort, Stable, IsSorted, Reverse, IntSlice, Float64Slice, StringSlice, Ints, Float64s, Strings, *AreSorted, xorshift, nextPowerOfTwo, lessSwap) | `src/sort.rs`, `src/pdqsort.rs` |
| `sort/slice.go` (Slice, SliceStable, SliceIsSorted) | `src/sort.rs` |
| `sort/search.go` (Search, Find, SearchInts, SearchFloat64s, SearchStrings, *.Search) | `src/sort.rs` |
| `slices/sort.go` (Sort, SortFunc, SortStableFunc, IsSorted, IsSortedFunc, Min, MinFunc, Max, MaxFunc, BinarySearch, BinarySearchFunc) | `src/slices.rs` |
| `cmp/cmp.go` (Ordered, Less, Compare) + builtin `min`/`max` (`runtime/minmax.go` strmin/strmax; arm64 `FMIN`/`FMAX` for floats) | `src/cmp.rs` |

The four `zsort*.go` files are generated by `sort/gen_sort_variants.go` from
one template; they differ only in how `less(i, j)` and `swap(i, j)` are
spelled (`data.Less(i,j)`, `cmp(data[i], data[j]) < 0`,
`cmp.Less(data[i], data[j])`). The Rust port translates the template once,
generic over the private trait `LessSwap { less(i, j), swap(i, j) }`, with
one adapter per variant. All indices are `isize` so Go `int` arithmetic
(e.g. `for i := (hi-1)/2; i >= 0; i--`, `int(uint(i+j) >> 1)`) ports verbatim.

## Public API (for downstream crates)

```rust
// package sort
pub trait sort::Interface { fn len(&self) -> usize; fn less(&mut self, i: usize, j: usize) -> bool; fn swap(&mut self, i: usize, j: usize); }
sort::sort(&mut impl Interface)              // sort.Sort (pdqsort)
sort::stable(&mut impl Interface)            // sort.Stable (insertion sort blocks of 20 + symMerge)
sort::is_sorted(&mut impl Interface) -> bool
sort::Reverse(I)                             // sort.Reverse; also impl Interface for &mut I
sort::LessSwapFuncs { len, less, swap }      // lessSwap as a struct of closures
sort::sort_less_swap(n, less(i,j), swap(i,j)) / sort::stable_less_swap(...)
sort::slice(&mut [T], |x: &[T], i, j| -> bool)        // sort.Slice
sort::slice_stable(&mut [T], |x, i, j| -> bool)       // sort.SliceStable
sort::slice_is_sorted(&[T], |x, i, j| -> bool)
sort::IntSlice(&mut [i64]) / Float64Slice(&mut [f64]) / StringSlice(&mut [S: AsRef<[u8]>])  (+ .sort(), .search())
sort::ints / float64s / strings (== slices::sort, as in Go >= 1.22), *_are_sorted
sort::search(n, f) / find(n, cmp) / search_ints / search_float64s / search_strings

// package slices
slices::sort(&mut [T: Ordered])              // slices.Sort (cmp.Less: NaN first, -0 == +0)
slices::sort_func(&mut [T], |a, b| -> Ordering)          // slices.SortFunc
slices::sort_stable_func(&mut [T], |a, b| -> Ordering)   // slices.SortStableFunc
slices::sort_less_func / sort_stable_less_func (boolean less)
slices::is_sorted / is_sorted_func / min / min_func / max / max_func / binary_search / binary_search_func

// package cmp
cmp::Ordered (ints, floats, String, &str, Box<str>, Arc<str>, Vec<u8>, &[u8], Box<[u8]>, Arc<[u8]>)
cmp::less / cmp::compare

// convenience
go_sort::sort_by(&mut [T], |a, b| -> bool)   // == sort.Slice / sort.Sort / slices.SortFunc
go_sort::stable_by(&mut [T], |a, b| -> bool) // == sort.Stable / sort.SliceStable / slices.SortStableFunc
```

A Go comparator returning `int` maps to `Ordering` with `n.cmp(&0)`;
`cmp(a, b) < 0` is the only thing the algorithms look at.

## Deliberate deviations

* `Interface::less` and `swap` take `&mut self` (Go methods may mutate
  through pointers; Rust needs it explicit). Call sequence is unchanged.
* `sort.Slice`'s `less(i, j)` closes over the slice in Go; in Rust the
  closure receives the slice (`&[T]`) as its first argument.
* Go `sort.StringSlice.Search(x string)` takes `&[u8]`; string element types
  are anything `AsRef<[u8]>` (bytewise order, same as Go).
* Float `min`/`max` (used by `slices.Min`/`Max`): on arm64 the Go compiler
  lowers the builtins to `FMIN`/`FMAX` (`ssagen.minMax` → `OpMin64F` →
  `FMIND arg0, arg1`), not to `runtime/minmax.go:fmin`. The two differ only
  in which NaN comes back when NaNs are involved; the port reproduces the
  ARM `FPProcessNaNs` rule with FPCR.DN=0 (signaling NaN first, quieted;
  op1 before op2), which the oracle confirms (the `runtime.fmin` rule fails
  816 fixture cases). `-0`/`+0` follow Go (`min` → -0, `max` → +0).

## FMA sites

None (no floating-point arithmetic).

## Verification

Oracle: `tools/go-oracle/go-sort` (`go run ./tools/go-oracle/go-sort -out
crates/go-sort/tests/fixtures/sort.txt -idsmax 24`). For each (variant,
comparator kind, input pattern, size, distinct-key count, seed) it sorts
splitmix64-generated input with the real Go functions and records the number
of comparator calls, an FNV hash of the full call trace (every less/cmp
argument pair and, for `sort.Interface`, every Swap), a hash of the resulting
order and, for n ≤ 24, the order itself. The Rust test regenerates the same
input bit-for-bit.

* Variants: `sort.Sort`, `sort.Stable`, `sort.Slice`, `sort.SliceStable`,
  `slices.SortFunc`, `slices.SortStableFunc`, `sort.Sort(sort.Reverse)`,
  `sort.Stable(sort.Reverse)`, `slices.Sort([]float64)` (NaNs with payloads,
  ±0, ±Inf), `sort.Sort(sort.Float64Slice)`, `slices.Sort([]int)`,
  `slices.Sort([]string)`, `slices.Min`/`slices.Max` over `[]float64` with
  quiet/signaling NaN payloads and signed zeros.
* Comparators: key compare with many ties, a random comparator (answer from
  a PRNG, depends only on the call index), and Go's own McIlroy adversary
  from `sort_test.go` (forces the heapSort fallback).
* Patterns: random, ascending, descending, sawtooth, organ pipe, all equal,
  nearly sorted, random runs, V shape; sizes 0..=80 plus 22 sizes up to 2000.
* Checked-in fixture: 20,582 cases, all identical. Scratch corpus with 12
  seeds per configuration (`-seeds 12 -idsmax 0`): 246,984 cases, all
  identical (release and debug builds).
* Mutation check: changing any of `j >= 1` (Go's partialInsertionSort
  quirk), the xorshift constants, the heapSort fallback, `length/8`,
  `shortestNinther`, the stable block size or the symMerge fast path makes
  the fixture fail (14 to 5,986 mismatches).

### Independent adversarial verification (second agent)

* Oracle mode `-dense` (`tools/go-oracle/go-sort`, `-maxn`, `-sizes`,
  `-every`): every size 0..=3000, every combo, one rotating input pattern
  per (size, combo), plus two extra comparator kinds on all eight
  comparator-driven variants: kind 3, a non-strict `a.key <= b.key`
  (cmp never returns 0), and kind 4, an inconsistent comparator hashed from
  the two element identities (independent of call order). Each case still
  records call count, the full less/swap trace hash and the result hash.
* Scratch runs: dense 0..=3000 (120,038 cases) and sizes 4095, 4096, 4097,
  8191, 10000, 32768, 65535, 100000, 262144 (360 cases): 0 mismatches
  (release). The default-mode fixtures regenerate byte-identically.
* `tests/fixtures/dense.txt` (12,004 cases, `-dense -maxn 3000 -idsmax 0
  -every 10`) is checked in and run by `oracle_dense`.
* `tests/go_tables.rs` ports Go's `TestFind`, `TestFindExhaustive`,
  `TestSearchExhaustive`, `TestSearchWrappers`, `TestBreakPatterns`,
  `TestReverseSortIntSlice` (sort) and `TestMinMax`, `TestMinMaxNaNs`,
  `TestMinMaxPanics`, `TestBinarySearch*` (slices).

## Known gaps

* `slices.Sort` for `uintptr`/named types is covered through the Rust
  primitive types only.
* `sort.Find`'s `cmp` returns `i32` (Go `int`); only its sign matters.
