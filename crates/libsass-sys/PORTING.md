# libsass-sys — porting notes

Vendored **LibSass 3.6.6** built the way `github.com/bep/golibsass@v1.2.0`
builds it, and a port of the golibsass Go wrapper. Hugo uses it for
`toCSS` with the default `libsass` transpiler
(`resources/resource_transformers/tocss/scss`).

## Go file → Rust module map

## Build (byte parity of the C/C++ code)

cgo's command lines (`go build -n`, go1.27.1 darwin/arm64, `CGO_*FLAGS` unset):

```
c++ -I . -fPIC -arch arm64 -pthread -fmessage-length=0 -fno-common -I<golibsass>/libsass_src/include -I $WORK/b002/ -O2 -g -g -std=c++0x -O2 -fPIC -c <unit>.cpp
cc  -I . -fPIC -arch arm64 -pthread -fmessage-length=0 -fno-common -I<golibsass>/libsass_src/include -I $WORK/b002/ -O2 -g -O2 -fPIC -c <unit>.c
```

`build.rs` uses `cc::Build::no_default_flags(true)` and passes exactly these
flags (profile-independent). Link: `-lm -ldl` plus the C++ runtime from `cc`
(libc++ on Apple; golibsass asks for `-lstdc++`, which is libc++ on macOS).
`LIBSASS_VERSION` is undefined, so `libsass_version()` is `"[NA]"` as in Go.

**Verified:** every unit compiled both ways (cgo stub in the golibsass module
dir vs. direct file with the build.rs flags): `objdump -d` text identical for
**64/64** objects (`$S/work/libsass-sys/objcmp/cmp.sh`).

## Public API (for the Hugo `toCSS` port)

```rust
let t = libsass_sys::new(libsass_sys::Options {
    output_style: libsass_sys::parse_output_style(b"compressed"), // OutputStyle(i64)
    precision: 8,                        // Hugo: 0 -> 8 (client_extended.go); 0 here keeps LibSass's default
    include_paths: vec![...],            // Vec<Vec<u8>>, joined with ':' (os.PathListSeparator)
    import_resolver: Some(Arc::new(|url: &[u8], prev: &[u8]| (new_url, body, resolved))),
    sass_syntax: false,                  // true for .sass input (runs sass2scss on the entry)
    source_map_options: libsass_sys::SourceMapOptions { filename, root, input_path, output_path, contents, omit_url, enable_embedded },
})?;
let r: libsass_sys::SassResult = t.execute(src_bytes)?; // r.css, r.source_map_filename, r.source_map_content (Vec<u8>)
// Err(libsass_sys::Error { status, column, file, line, message }); Display == Go Error()
```

All strings are bytes (`&[u8]`/`Vec<u8>`), as Go strings. Hugo-level logic
(`replaceRegularImportsIn/Out`, the resolver closure with `MakePathRelative`,
the `stdin` → real filename error remap, the source-map `stdin"`
replacement) belongs to the Hugo layer, not this crate.

Import resolver semantics (`BridgeImport`), preserved exactly:
* called for every `@import` LibSass hands to custom importers, with
  `url` = the import URL and `prev` = `imp_path` of the last entry on
  LibSass's import stack (`"stdin"` for the entry; the resolver's `new_url`
  for resolved imports; the URL as written for imports LibSass resolved
  itself);
* `(new_url, body, true)` with non-empty body → `sass_make_import_entry(new_url, body)`;
  with empty body → LibSass loads `new_url` from disk;
* `resolved == false` → `sass_make_import_entry(url)` (LibSass resolves it);
* Go `C.CString` semantics: a body/path with a NUL byte is truncated there.

## Deliberate deviations

1. **Memory ownership.** Go leaks the `C.CString`s passed to the copying
   option setters and to `sass_make_import_entry(path)`, frees the output
   string and error JSON itself, and never deletes the data context. Rust
   frees the temporary strings, copies the outputs, and deletes the
   compiler and the data context (which frees output/error strings and the
   importer list). No output change.
2. **Resolver panics.** A panic inside the resolver cannot unwind through
   C++; it is caught, the import is treated as unresolved, and the panic is
   resumed after the compile returns (Go would crash in the cgo callback).
3. **`sass2scss` result** is freed after copying (Go leaks it).
4. `new` returns `Result<LibsassTranspiler, Error>` (Go returns the
   `Transpiler` interface; its error is always nil).
5. `parse_output_style` uses ASCII case folding; Go's `strings.ToLower`
   gives the same results because no non-ASCII rune lowers to a letter used
   in `nested|expanded|compact|compressed`.
6. `json_to_error` is a small decoder implementing the `json.Unmarshal`
   behaviour needed here: whole-document validation first (invalid → zero
   `Error`), case-insensitive field names (with `ſ`/`K` folding), last
   duplicate wins, type mismatches leave the field unchanged, int fields
   reject fractions/exponents/overflow, Go string unescaping (invalid UTF-8
   and unpaired surrogates → U+FFFD).

## FMA sites

None on the Rust side (no float arithmetic). All number formatting and math
is in the C++ code, compiled with cgo's compiler and flags (identical machine
code, see above).

* `tests/oracle.rs` — **254** cases from `tools/go-oracle/libsass-sys`, all
  byte-identical (CSS, source-map filename and content, error string and
  fields, and the full importer call trace `(url, prev)`):
  * seeksnack `assets/scss/website.scss` with Hugo's settings (include paths

    precision 0/3/5/10, Hugo's `enableSourceMap` options, embedded and
    omit-URL source maps. The Go oracle checks that its compressed output
    equals neohugo's real toCSS output (`$S/work/resources-pipeline/libsass.out.css`,
    315116 bytes) — so the Rust output equals the Hugo output too;
  * the golibsass `transpiler_test.go` cases;
  * 45 feature snippets × 4 output styles, precision sweep 0-20, 12 error
    snippets, indented syntax;
  * import bridging: bodies with nested imports (`prev` = parent's
    `new_url`), path-only resolution, unresolved → LibSass include paths →
    nested `prev`, NUL in body, empty `new_url`, `resolved=false` with
    values, missing file, unicode/space URLs, multi-imports, CSS/url()
    imports, import inside a rule, indented body/file, error inside a body,
    source map through an importer;
  * Hugo resolver over extra files (`_partial`/`partial.scss`, `_index`,
    `index`, `_x.scss` vs `x.scss` preference, relative `../`, `.sass`
    partials, `.css`, `vendor` mount, `hugo:vars`, not found).
* `tests/golibsass_tests.rs` — port of golibsass `transpiler_test.go`
  (incl. the 10×10 and 10×100×10 concurrency tests), resolver panic
  propagation, version string.

Regenerate fixtures (repository root):

## Known gaps

* `Error`'s `%q` of the file name uses an approximation of Go's
  `unicode.IsPrint` for non-ASCII runes (exact for ASCII). Switch to the
  `go-strconv` crate's `quote` once it is available.
* Platforms. The fixtures come from darwin/arm64 (Apple clang 21, libc++).
  On other hosts `build.rs` compiles with clang/clang++ (unless `CC`/`CXX`
  is set) and adds `-ffp-contract=on` and, on x86_64, `-mfma`, matching
  Apple clang's FMA contraction on arm64. Verified on linux/x86_64 (Ubuntu
  clang 18.1.3 with libstdc++): every test passes, including 2052/2052
  oracle cases. With gcc 13, 194/2052 differ, all in error positions
  (e.g. `@error` reports the real column instead of Apple's column 1):
  LibSass builds a `SourceSpan` from arguments with side effects, and gcc
  evaluates C++ call arguments right to left where clang goes left to
  right. libstdc++ vs libc++ made no observable difference in the corpus.
  `NEOHUGO_NO_FMA=1` drops `-mfma` for CPUs without FMA3.
* The golibsass `dev` build tag (link a system libsass) is not supported.
