# neohugo Rust port — crates

neohugo is being ported from Go to Rust. The acceptance test is byte parity:
the Rust binary must build the seeksnack site into output that is byte-identical
to the Go build. Every crate here is therefore a *faithful port* of the Go
code that produces those bytes, not a reimplementation from a spec.

The Go sources stay in this repository as the reference implementation until
parity is reached.

## Layout

- `crates/<name>/` — one Rust crate per Go package cluster.
- `tools/go-oracle/<name>/` — Go programs (package `main`, inside this Go
  module so they can import the exact dependency versions from `go.mod`) that
  generate test fixtures from the real Go code.
- `crates/<name>/tests/fixtures/` — fixtures generated by the oracle and checked
  in, so `cargo test` never needs a Go toolchain.
- `crates/<name>/PORTING.md` — Go file → Rust module map, deliberate
  deviations, known gaps.

## Porting rules

1. **Port, don't reinvent.** Translate the Go code function by function,
   keeping the structure, names (in snake_case) and control flow, so a reader
   can diff Rust against Go. Put `// Go: <path>:<Func>` above each ported
   function. Deviations must be listed in `PORTING.md`.
2. **Byte parity is the only correctness criterion.** A Rust crate that
   "does the same thing" but produces different bytes is wrong. Do not
   substitute crates for Go logic that affects output. Crates that are
   allowed because they cannot change output bytes: `xxhash-rust`, `sha2`,
   `sha1`, `md-5`, `base64`, `hex`, `crc32fast`, `adler`/`adler32`, `memchr`,
   `cc`, `libc`, `unicode-normalization` (NFC/NFD only),
   `miniz_oxide`/`flate2` (decompression only), `unsafe-libyaml` (as a YAML
   event source only). Anything else needs a written justification in
   `PORTING.md`.
3. **Go strings are bytes.** Where Go uses `string`/`[]byte` for text that may
   be arbitrary input (markup, templates output, minifier input), use
   `&[u8]`/`Vec<u8>`/`GoString`. Decode UTF-8 with Go's rules (invalid byte →
   `U+FFFD`, width 1) from `go-unicode`'s `utf8` module, never with
   `String::from_utf8_lossy` semantics in parity paths.
4. **Unicode = Go's tables.** Never use `char::is_alphabetic`,
   `char::is_numeric`, `str::to_lowercase`, etc. in parity paths. Use
   `go-unicode`, whose tables are generated from go1.27.1 (Unicode 17.0.0).
5. **Integer semantics.** Go integer arithmetic wraps; use `wrapping_*` where
   Go code relies on it. Go `int` is 64-bit. Conversions `int(f)` from float:
   match Go (truncation; out-of-range/NaN behaviour on arm64 is saturating,
   `NaN → 0`, which is also what Rust `as` does).
6. **Floating point and FMA.** The golden output was produced on
   darwin/arm64. The Go compiler on arm64 fuses `x*y + z`, `x*y - z`,
   `z - x*y` into a fused multiply-add when the product has no other use and
   there is no explicit conversion around it (`float64(x*y) + z` is NOT
   fused). Replicate every such fusion with `f64::mul_add`/`f32::mul_add` in
   exactly those places. When a crate does float arithmetic that reaches
   output bytes, verify with `go tool objdump` of the oracle binary (look for
   `FMADD`/`FMSUB`/`FNMADD`/`FNMSUB`) and note each fused site in `PORTING.md`.
7. **Sorting.** Go `sort.Sort`/`sort.Slice` are unstable (pdqsort) and
   `sort.Stable` is insertion sort + symMerge. When a comparator has ties,
   use the `go-sort` crate so tie order matches Go. Rust's `sort_by` is only a
   substitute for comparators with no ties.
8. **Map iteration.** Go randomises map iteration. Wherever Go output
   depends on map order, Go code sorts first; port that sort. Use `BTreeMap`
   for Go's sorted-key behaviour.
9. **No panics on input.** Go returns errors; return `Result`. Panics are
   only for true invariants.
10. **Tests.** Every crate has differential tests against fixtures produced by
    its Go oracle (`tools/go-oracle/<crate>`), covering the real seeksnack
    inputs where applicable and adversarial/edge cases. Port Go's own
    `_test.go` tables where they exist. `cargo test` must pass with no
    network and no Go toolchain. Keep checked-in fixtures reasonably small
    (a few MB per crate); larger corpora go outside the repo.
11. **Style.** Rust edition 2024, `cargo fmt`, `cargo clippy` clean (allow
    lints that fight a faithful port, e.g. `too_many_arguments`,
    `needless_range_loop`, with a crate-level `#![allow(...)]` and a comment).
    No `unsafe` outside the `*-sys` crates.
12. **Standalone crates (temporary).** Until all crates are merged into one
    workspace, every crate's `Cargo.toml` ends with an empty `[workspace]`
    table and depends on siblings by path (`go-value = { path = "../go-value" }`).
    Build with a private target dir: `CARGO_TARGET_DIR=<scratch>/targets/<crate>`.
13. **Ownership.** Only edit the crate(s) you were assigned and their oracle
    directory. If you need a change in another crate, ask for it in your
    report instead of editing it.
